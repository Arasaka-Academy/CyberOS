这份文档是 CyberOS 主 Web、TV 和文档站的共同设计规范。业务需求可以改变信息和流程，但不能在局部 CSS 中建立另一套颜色、几何或交互语言。三端共享基础令牌和状态语义，并分别适配操作密度、远距离观看与长文阅读。

视觉体系采用 CyberUI v0.2.2 的配色、字体、切角装饰与组件源码，固定来源和适配记录见 `packages/ui/UPSTREAM.md`。保留 CyberOS 的布局、导航、业务控件语义和高密度操作方式；七套配色各有明暗模式，三端共享同一套语义令牌。

## 1. 产品性格

CyberOS 的定位是“A personal operating system for the cyber era”，当前以原生 Linux 服务承载个人文件、媒体、AI 工作流与主机管理。界面要像可操作的设备菜单，而不是营销页或装饰性 dashboard。

- **高密度、可扫描**：优先展示状态、数据和下一步操作，使用稳定列、硬分隔线和清晰对齐。
- **完整主题体系**：支持 neon、mono、graphite、synthwave、bloodline、terminal、amber 七套配色与 dark/light 两种模式。默认 neon/dark，不提供跟随系统。偏好仅存当前浏览器，同源 Web 与文档共享；TV 浏览器单独保存。
- **清晰结构**：背景、表面、文字、结构线与主/次强调色随主题变化。1px 结构线与选中状态轨建立层级，主强调色用于命令和当前入口。
- **尺度反差**：标题短、粗、紧凑；技术元数据使用更小的等宽文字。面板内不使用 hero 级字号。
- **状态可验证**：颜色必须同时配合图标、文字、ARIA 状态或结构位置，不能只靠红色或青色传意。
- **启动状态准确**：页面资源加载较慢时保持加载状态与 `aria-busy`，可以提供手动重载入口；只有实际启动错误才显示失败。资源随后就绪时自动进入工作区。
- **流程不变**：视觉改造不能绕过审批、安全边界、焦点管理或现有操作步骤。

不应出现巨型 hero、装饰性渐变球、胶囊控件、柔和圆角卡片、卡片套卡片、持续闪烁、第三方品牌标志或解释界面风格的可见文案。

## 2. 应用骨架

### 桌面

根布局保持 Agent / Workspace 双工作区，中间是支持鼠标和键盘的工业分隔结构。

- `.app-shell` 占满视口；Agent 最小宽度 `560px`，Workspace 最小宽度 `460px`。
- Agent 聊天页头与所有 Workspace `PanelHeader` 必须复用 `.app-titlebar` 和 `--app-titlebar-height`，桌面总高度固定为 `70px`，两侧底边基线不得错位；移动端统一为下述 `104px` 双层标题头。底部分隔线统一为 `1px` 的 `--cyberos-hud-red-soft`，不得按面板覆盖成灰色。桌面 Agent 导航 Logo 区的底部分隔线也必须对齐桌面基线，计算 Logo 区高度时需扣除导航轨顶部内边距。
- Agent 导航是主题控制轨，只展示普通 Agent 会话，按会话类型排除系统语音会话，不能依赖会话标题过滤；移动端会话弹窗沿用相同规则。默认打开与删除后的回退只选择普通会话，没有普通会话时创建新会话。系统语音的日常入口保留在底部语音按钮，完整语音会话和审批仍从语音抽屉进入。当前普通会话使用强调色选中面和强调色左轨，编号不受被隐藏的系统语音会话影响。
- Agent 输入区只保留文本框与固定 `40px` 高的底部操作行；发送、排队、运行、重连与结束状态不得新增或删除布局行，不得改变输入框高度或推动聊天记录。底部左侧在模型信息与运行状态之间原位切换，状态使用轻量图标和单行省略文字，完整状态与模型信息通过自定义悬浮提示查看，并保留无障碍实时播报。右侧并列放置“插入指令 / 后续处理”图标切换与停止、发送操作，均使用有提示和无障碍名称的直角图标按钮，投递方式保留选中态；只有附件等用户主动添加的内容可增加输入区高度。
- Workspace 是主题操作画布，最右侧面板导航使用主题轨道，当前面板使用强调色选中面和强调色状态轨。
- 桌面左右导航轨均保持 `72px` 宽，使用同一主题表面和 `1px` 结构分隔线。按钮统一 `48px` 宽，左侧图标入口高 `44px`、右侧图文入口高 `52px`，间距为 `6px`；图标为 `20px`，右侧短标签为 `11px`。`8px` 切角仅裁切无交互装饰层，按钮与焦点环不能被裁切；当前项使用主强调色填充、反色文字、短状态轨与 `2px` 硬偏移底板，普通项保持低强调，hover 使用次强调色边线和浅底，键盘焦点环独立显示。无文字电源入口必须声明为图标按钮，不能继承文字命令的最小宽度。新建区不使用挤占按钮宽度的独立 `//` 装饰，会话编号与审批角标分开定位。会话列表独立滚动、底部工具固定，短视口右轨可滚动；骨架沿用相同按钮尺寸和底部分区高度，切换状态不改变布局。导航规则只作用于桌面轨道，不覆盖移动端会话弹窗或共享按钮。
- 分栏拖拽区使用 `14px` 网格列，拖动条必须填满该列；`2px` 低强调色中线严格居中，两侧各留 `6px`，禁止拖动条与网格列宽度不一致造成单侧多余留白。中部使用 `4px × 32px` 强调色抓手，不使用双线或多色装饰。hover、键盘聚焦与拖动时增强反馈，键盘焦点环保持清晰；交互状态不能改变热区宽度或推动两侧内容。
- 页面骨架固定，面板内容在自身区域滚动；隐藏原生滚动条不能损失滚轮、触控板、触摸或键盘滚动。
- 桌面 Web 播放入口位于左侧 Agent 导航设置按钮正上方，沿用侧栏按钮尺寸、提示和焦点样式，以静态标记和无障碍名称区分空闲、播放、暂停、异常。桌面底部不分配播放栏或恢复入口行，左右导航占满可用高度；窄屏使用下述公共播放栏。切换面板或断点不卸载播放状态和视频节点。
- 常驻区块使用完整画布和分隔线。只有可拖拽组件、审批项、重复交互项、弹窗和明确工具才使用封闭框。
- **无必要不等分块**：独立功能、配置和状态区块默认纵向排列，每块占据所在内容容器的一整行。不得仅为填满宽屏或追求对称而使用二等分、多等分布局；只有明确需要并列比较、紧密关联的字段或用户自定义工作区时才采用多列，并保证窄屏阅读顺序和可用宽度。

NVR 采用卡片组织四个页签：实时页以全宽总览卡开头，摄像机、录像片段和事件作为同类交互卡片；存储、筛选、时间轴和添加设备等功能卡保持全宽。同类卡片按内容容器宽度在 `620px` 切换单列和双列，卡片内部沿用共享字段、状态及操作，不重复套框。摄像机卡片保留实时小画面，点击后通过共享模态层打开画面与云台；弹窗暂停背景预览、关闭后恢复，移动端返回、键盘焦点与云台停止语义保持一致。

### 窄屏

窄屏使用 应用主屏启动器和全屏 App，桌面保留双工作区：

| 边界 | 规则 |
| --- | --- |
| `1040px` | 切换主屏和全屏 App，隐藏常驻 Agent 会话侧栏与 Workspace 导航轨；主屏网格六列。设置使用分类列表及详情页。 |
| `560px` | 主屏网格四列；Dock 始终为四项。 |
| `620px` | 管理区和文件区堆叠；页头保留返回、标题、主操作及主屏入口，次要操作进入更多菜单。 |
| `520px` | 预览隐藏次要文件列；Photo 瀑布墙固定两列。 |
| `360px` | Composer 保持单行操作区，状态文字优先省略，图标按钮与输入不能溢出或换行。 |

验收覆盖 `1440/820/560/390/320px`，中文和英文各检查一次。长文件名、路径、错误和按钮文案必须省略、安全换行或缩放容器，不能制造页面级横向滚动。

- App 登记表由桌面和手机共享，包含全部十三个面板及 Agent、设置。主屏固定顺序为影视、下载、监控、NVR、Docker、虚拟机、网络、存储、共享、终端、设置；Dock 固定为文件、照片、音乐、Agent，不重复网格入口。
- 主屏展示 CyberOS、实际 API 连接状态及通知入口。连接状态仅表示连接可用，不能代表存储池或备份就绪。移动电源入口放入设置的系统页，复用现有确认流程。
- 图标使用约 `56px` 硬切角底板、Lucide 图形、短名称和硬偏移阴影；切角只裁切装饰层，不裁切按钮焦点环。首版固定布局，不提供排序、文件夹、小组件或最近任务。
- `#/home` 和 `#/app/<id>` 使用浏览器历史。无地址或未知地址回主屏；有效地址直接进入 App。返回依次关闭顶层弹窗、退出详情或预览、返回上一站内页面，无可返回记录时进入主屏；主屏按钮直接进入主屏。
- 当前面板由应用层受控；跨断点复用同一播放器、上传与 Agent 连接。退出 App 后卸载页面轮询和重型内容，用标签页内存快照恢复目录、核心媒体筛选、详情标识、滚动位置和 Agent 草稿，不新增持久化凭据。
- 公共播放栏占独立布局行：主屏时位于 Dock 上方，App 中位于内容下方。仅主屏显示 Dock；最底部可见行承接安全区，不能覆盖内容或 Composer。全屏播放延续现有隐藏规则。
- 触控区域至少 `44×44px`，移动输入字号至少 `16px`；骨架适配动态视口、软键盘及安全区。后台任务继续运行，恢复前台时同步真实进度与连接。
- 所有 App 的移动标题头复用 `MobileAppHeader`，总高度 `104px`：上层为 `36px` 强调色图标底板、强调色 `//` 前缀、`20px` 标题和 `12px` 单行说明；下层为独立主题操作轨，返回与主屏使用图标加短标签，直接主操作及更多入口保持 `44px` 操作面。沿用 PC 页头的主题表面、文字与结构分隔线，不能通过隐藏图标、前缀及说明来压成仅有导航按钮的一行。长标题和说明单行省略，操作轨不挤占标题空间。
- Agent 移动页头以 Agent 为标题、当前会话名称为说明；设置分类与详情提供各自图标、标题和说明，详情返回保持原分类导航。按需加载期间使用同一标题头和高度，避免页面就绪时布局跳动。更多菜单相对整个操作轨定位，遵循动态视口的剩余高度在内部滚动，不能因触发器位置或短视口被裁切；关闭后恢复入口焦点。

## 3. 品牌与资产

- CyberOS 图标和文字是第一视口的品牌信号。空间受限时只显示图标，设置和启动界面使用“图标 + CyberOS”。
- 图标保持现有几何和比例，通过共享的 `--cyberos-logo-filter` 适配深浅背景，不建立 Cyberpunk 标志或第三方联名版本。
- 不引入 Behance 图片、游戏截图、Cyberpunk logo、专有字体或从参考项目提取的图形文件。
- 图形装饰只由 CSS 结构线、状态轨、编号和短切角构成，不创建仿冒品牌素材。

## 4. 视觉令牌

### 字体

字体均自托管：Oxanium 的 TTF 和 OFL 许可随 CyberUI 源码保存在 `packages/ui/src/fonts/`；Noto Sans SC 由 Fontsource 提供；Share Tech Mono 的 WOFF2 和 OFL 许可在 `packages/shared/src/fonts/`。

- 导航、标题、按钮和数字层级使用 `Oxanium`，中文回退到 `Noto Sans SC Variable`。
- 文档长文与中英文正文优先使用 `Noto Sans SC Variable`。
- 技术元数据、路径、代码和终端使用 `Share Tech Mono`，缺失字符回退系统等宽字体；代码默认 `12px`。
- 不提供浏览器级字体或字号设置，不读取旧字体偏好。

正文通常为 `12-14px`；面板标题通常为 `17-22px`。标题、页签和命令可使用大写英文；中文保持原文，不增加字距。任何字号都不得随视口宽度连续缩放。

### 颜色

颜色由 `packages/shared/src/cyberui-tokens.ts` 的固定上游算法生成。`appearance.ts` 映射 CyberOS 语义；`appearance.css` 和原生播放色板 JSON 由 `npm run appearance:generate` 生成，`appearance:check` 防止产物漂移。组件不得写死某套主题的颜色。

| 角色 | 令牌 | 用途 |
| --- | --- | --- |
| 背景 / 表面 | `--cyber-bg` / `--cyber-soft` | 应用、弹窗、TV 和长文底面。 |
| 正文 / 次文字 | `--cyber-ink` / `--cyber-muted` | 深浅模式均保持可读；`ink` 表示文字。 |
| 命令 / 反色字 | `--cyber-accent` / `--cyber-on-accent` | 主命令、当前入口。 |
| 焦点 / 反色字 | `--cyber-accent2` / `--cyber-on-accent2` | 键盘、遥控焦点与菜单选中。 |
| 强调文字 / 链接 | `--cyber-accent-text` / `--cyber-accent2-text` | 正文、代码、链接和控件文字；在背景、抬升面及状态浅底上保证对比度。 |
| 结构线 | `--cyber-line` | 面板分隔与控件边框。 |
| 状态 | `--cyber-danger` / `--cyber-success` / `--cyber-warning` | 风险、成功和警告，必须配合文字或图标。 |

旧 `--cyberos-hud-*` 与 Web/TV 组件变量是兼容语义别名，不再定义固定色板。不要将旧黑底含义的 `--cyber-ink` 带回组件。主题更新只改变呈现，不重建上传、播放、终端或 Agent 连接。TV 通过现有 VOD 命令通道同步原生 mpv 控件，播放中和后续播放均应用当前主题；同步失败提供重试。

强调填充、边框和焦点环保留上游原色，不能直接用作小字号文字。文字使用 `--cyberos-color-{command,focus,connected,success,warning,danger}-text` 语义别名；对比不足时适配层回退到主题正文色。次文字也必须覆盖抬升与 hover 表面。Provider 与 Portal 继承同一组文字别名，避免上游内联变量覆盖；选中命令同步更新切角装饰层的 `--face`、`--edge` 与反色文字。

### 几何

- 默认圆角为 `0`。封闭面板用 `8/12/18px` 视觉切角、角标或不裁切内容的 CSS 结构装饰。
- 按钮的零圆角是强制约束，包含图标、关闭、取消、保存、危险操作和弹窗内按钮，不能作为页面局部可覆盖的默认值。
- 不在包含可聚焦子项的容器上使用会裁掉焦点环的 `clip-path`。焦点环必须完整显示在控件外侧。
- 边框以 `1px` 结构线为主；当前选择和关键分隔使用 `2-5px` 状态轨。
- 主操作可使用 `3-5px` 主题阴影硬偏移底板。hover 位移最多 `1px`，active 不缩放控件。
- 图标按钮具有稳定宽高和至少 `32px` 操作面；窄屏触控操作至少 `44×44px`。
- 间距沿用 `4/6/8/10/12/14/18/20/24/32px` 的紧凑节奏。

## 5. 组件状态

按钮、图标按钮、输入框、选择器、页签、表格行、菜单、Toast 和对话框必须覆盖：default、hover、active、selected、focus、disabled、busy、error。

- **Switch 与 checkbox**：启用/禁用、自动启动、只读模式等单一布尔设置统一使用共享 HUD Switch，并暴露 `role="switch"` 与 `aria-checked`。checkbox 只用于多选列表、筛选条件、权限选择和危险操作确认，不能用原生 checkbox 表现服务开关。

- **Hover**：深色表面使用次强调色边框、次强调色角标或轻微抬升层，不把整块内容染成高饱和色。
- **Active**：位移最多 `1px`，硬偏移底板收紧；禁止缩放。
- **Selected**：强调色状态轨配合反色面、图标或 `aria-selected` / `aria-pressed`。
- **Focus-visible**：Web 与文档站使用 `2px var(--cyber-accent2)` 外环和 `3px` offset；TV 为远距离遥控使用 `3px` 外环和 `4px` offset，公共播放栏与浮窗按钮也必须覆盖。焦点环不能被切角或父容器裁切。
- **Disabled**：降低对比但保持文本可读、尺寸稳定和 `not-allowed` 指针。
- **Busy**：使用主强调色与匹配反色文字、稳定尺寸、`aria-busy="true"` 和 spinner 或忙碌图标。
- **加载骨架**：复用 `--skeleton-base` / `--skeleton-highlight`，由主题正文与主题表面混合，保持直角、稳定占位和可见对比；禁止使用接近黑色的透明渐变覆盖深色面板。保留现有扫光与呼吸动效，减少动态效果时关闭动画但仍显示骨架。
- **首次加载**：桌面与移动 App 的按需模块加载均保留同高 `PanelHeader`、原面板标题和说明，忙碌图标放在页头按钮内，内容区使用共享骨架；不得用独立 Loading 文本替代整个面板。音乐与影视的数据加载复用刷新按钮的忙碌态，下载复用创建按钮的忙碌态，移动端将这些按钮保留为直接主操作。后台终端的模块加载不能阻塞当前面板。
- **Error**：红色边框或轨道必须配合错误图标、文案或 `role="alert"`。

常见操作使用 `lucide-react` 图标。纯工具操作优先图标按钮并提供本地化的 `aria-label` 和 `data-tooltip`；明确命令可使用图标加短文本。所有操作使用真实语义元素。

### 按钮（强制）

- **所有按钮必须直角**：原生 `button`、按钮类型的 `input` 和语义为 `role="button"` 的控件，四角均为 `0`；普通按钮、图标按钮、关闭按钮、页签、菜单操作与 Switch 一并遵守。`summary` 折叠入口及其内部绘制可见边框或背景的触发外框也必须直角，不能只检查可聚焦根元素。禁止圆角、胶囊形或圆形按钮，也禁止通过按钮伪元素背景变相添加圆角。
- 主操作使用主强调色和配套反色文字；次操作使用主题表面、正文色与结构边框；危险操作复用危险色及已有确认流程。颜色、字体、间距和硬偏移底板复用共享令牌，不另建页面风格。
- default、hover、active、selected、focus-visible、disabled 和 busy 状态均保持四角为 `0`、操作面尺寸稳定。图标按钮至少 `32px`；直角造型不能缩小触控区域或裁掉次强调色焦点外环。
- 所有 Workspace 面板页头右侧操作统一复用 `PanelHeaderAction` 与 `management/header-actions.css`，以文件面板为基准：桌面 `32×32px`、`18px` 图标、`6px` 间距、细结构边框和低强调底色；悬停使用次强调色填充、配套反色图标与 `3px` 主强调色硬偏移阴影，按下收紧偏移。选中与忙碌使用共享主强调色，危险操作保留危险色，禁用保持尺寸稳定。键盘焦点环不裁切；移动端和触控至少 `44×44px`，次操作继续进入带文字的更多菜单。文件、媒体或管理面板不得另行覆盖页头按钮外观，内容区按钮不受此规则影响。
- **规则不依赖挂载位置**：弹窗、嵌套弹窗、全屏层和挂载到 `document.body` 的 Portal 都必须生效。Web 的 `brand.css`、TV 的 `tv.css` 与文档站的 `custom.css` 均使用全局 `border-radius: 0 !important` 约束按钮、语义按钮及其伪元素，不能依赖局部工作区祖先；基础主、次、危险按钮也直接定义为 `0`。
- 新增或修改按钮时禁止通过局部 CSS、内联样式、单角半径、交互状态或 `!important` 覆盖直角约束。验收检查浏览器计算样式中的四个角均为 `0px`，并覆盖主按钮、次按钮、危险按钮、图标按钮及 Portal 场景。

### 组件结构与归属

#### Card、Panel 与 Section 的视觉契约

以固定的 CyberUI v0.2.2 为准，三者不能混用：

| 容器 | 视觉效果 | 适用对象 |
| --- | --- | --- |
| `Card` / `.ui-card` | `--cyber-soft` 底面、正文色、直角；无边框、渐变、光晕和投影。默认内边距 22px，手机 18px；密集内容显式 compact 为 14px，媒体显式 none。 | 可独立理解的摘要、设备、录像、事件、专辑和影片；媒体继续保持原图像比例。 |
| `Card variant="frame"` / `.ui-card.ui-card-frame` | `--cyber-bg` 底面与单层 1px `--cyber-line` 结构框，无默认阴影。是 CyberOS 对上游 Panel 的密集适配；上游 Panel 默认 2px，原组件及 shape API 保持不变。 | 可拖拽管理组件、审批等独立工具；只在最外层绘制框，内部 Section、指标和列表不再叠框。 |
| `Section` / `SectionHeader` | 透明底、顶部结构线，标题 15px/24px、说明 12px，图标槽 24px、图形 18px。 | 常驻设置、协议服务、详情分组、筛选与表单。类名含 card 不构成使用封闭卡片的理由。 |

`CardHeader` 复用 SectionHeader 的图标、标题与操作槽，卡片头不重复绘制分隔框。上游 Card 的标题 20px 在高密度 Web 中适配为 15px；TV 保留现有远距字号，文档保留阅读字号。组件接收原生 article 属性和 ref，不引入点击、选择、请求或连接状态。

原生 button、a、li、section 和网格容器可以消费 `.ui-card` 外观契约，保留原语义；不能为套卡片新增可点击 div、嵌套按钮或改变列表结构。已有媒体卡保持比例和标题省略，照片选择使用主强调色轨与选择语义；普通 hover 只加强次强调色边线，不移动卡片、不增加阴影。键盘焦点使用独立外环，TV 为 3px/4px，Web 为 2px/3px；只裁切图片，不裁切整个交互容器。审批保留风险文字及确认，未读记录使用主强调色轨，错误和忙碌仍由共享反馈组件表达。

卡片家族的呈现由共享 `cards.css` 和 Web 的 `components/cards.css`、`card-details.css` 适配层维护；业务 CSS 只维护布局、尺寸与实际数据状态，不再在 files/theme、dark-surfaces、settings/theme 等通用皮肤中重复绘制卡片。管理摘要及 Dashboard、Docker/VM/网络/存储详情、iSCSI、NVR、Agent 审批、媒体缩略图、下载/通知/告警记录、设置指标、手机入口、TV 海报/搜索/剧集和文档 Card/LinkCard 均按此分类。下载、通知、资源和设备列表仍是结构线分隔的记录，避免把每行转换成独立工具面板。

| 契约 | 唯一呈现所有者 | 消费约束 |
| --- | --- | --- |
| 命令和图标操作 | `@cyberos/ui` 的 `Button` / `IconButton`，`controls.css` | 显式 variant、size、iconOnly；保留原生 ref、事件、submit、required 和 disabled 语义。busy 不改变操作面尺寸。 |
| 字段 | `Field` / `Input` / `Textarea` / `Checkbox`，`controls.css` | `Field` 独占 label、帮助、错误关联；一个字段包含一个主控件。帮助按钮独立于 label；合并已有 aria-describedby，不覆盖其他说明。代码编辑器、Composer、文件上传和提交式滑杆保留专用输入契约。 |

| 键值详情 | `DescriptionList`，`sections.css` | 使用语义化 dl/dt/dd，统一标签、值和补充说明的对齐与换行；业务值允许链接、图标及其他 React 内容。 |
| 选择与开关 | `CustomSelect` / `Switch` | 选择器接入 Field 上下文，保留必填校验与菜单焦点；Switch 保留原生布尔事件。checkbox 不冒充服务开关。 |
| 常驻区块 | `Section` / `SectionHeader`，`sections.css` | 全宽纵向、顶部结构线；图标、标题/说明和操作各有固定槽位。可拖拽管理组件保留自己的封闭框。 |
| 卡片与独立工具 | `Card` / `CardHeader`，`cards.css` | soft 默认，独立工具显式 frame；padding 显式选择，外观不承载业务状态与事件。原生元素可消费同一类契约。 |
| 错误、空状态、标记 | `Notice` / `EmptyState` / `StatusBadge`，`feedback.css` | tone/state 为显式属性；操作和图标进入独立槽位；后台状态不用反复 alert，状态标记不自动建立 live region。 |
| 模态标题与操作区 | `DialogHeader` / `DialogActions`，`dialog.css` | 标题/说明 ID 不变，长内容在正文内滚动。层级、Escape 和焦点仍由 ModalPortal/useModalDialog 管理，不能建立第二套模态状态。 |
| 面板与移动骨架 | `PanelHeader` / `MobileAppHeader` | 保留 70px/104px 标题、返回栈、直接操作及更多菜单；移动设置详情只呈现 MobileAppHeader；跨断点不重建播放器和会话。 |

### 样式组织与复用

- `styles.css`、`workspace.css`、`settings.css`、`brand.css`、`hud-workspaces.css`、`responsive.css`、`chat.css`、`photos.css`、`monitoring-alerts.css` 与 `tv/tv.css` 是聚合入口，只维护导入顺序。基础映射在 `styles/foundation/`，共享控件在 `styles/components/`，业务规则归入文件、下载、网络、存储、Docker、VM、终端、聊天、照片等所属目录。响应式规则跟随所属模块；全局骨架响应规则位于 `foundation/responsive.css`。
- 业务样式以 200–600 行为维护目标，单文件不得超过 800 行。不得为行数目标拆出编号片段；文件名表达职责。文件拆分首先保持声明和导入顺序，再通过计算样式及交互回归确认有意的统一调整。
- 第三方全局样式在聚合入口进入命名层，再由业务布局覆盖。MapLibre 样式先进入 `legacy` 层；不得在组件中以无层级 CSS 导入覆盖地图容器的定位和尺寸。
- 基础颜色以共享 `appearance.ts` 及生成的 `appearance.css` 为准，Web/TV 共用 `foundation/tokens.css` 的完整组件映射。新增变量必须有定义或明确回退；仅动态数据值由组件设置。禁止使用未定义的 `--border`、`--panel`、`--focus-ring` 等局部别名。
- 命令使用 `Button variant="primary|secondary|danger"`；轻量操作使用 `plain`，有业务布局的导航入口使用 `ghost`。图标操作显式使用 `iconOnly` 或 `IconButton`，不从业务 class 推测角色。原有类只承载布局和特征定位。默认命令高 `34px`，显式 `size="compact"` 为 `32px`，不得通过 `.某页面 button` 改变公共按钮尺寸、禁用透明度或忙碌颜色。移动触控至少 `44px`，TV 默认命令为 `48px`。
- 所有 Web/TV 下拉框统一使用 `CustomSelect`，ESLint 检查全部 Web TSX。字段默认高 `40px`；紧凑字段通过 `className="control-compact"` 显式选择 `34px`，移动触控至少 `44px`；TV 字段和选项保持 `48px`。菜单统一主题表面、次强调色选中面和明确选中语义，不能按页面重设配色。菜单挂到当前模态或应用浮层，以视口定位并随滚动更新，避免正文裁切；Escape 只关闭当前层。
- 必填下拉使用 `required`，校验失败后聚焦可见触发器并展示关联错误；`triggerRef` 用于恢复焦点，`ariaBusy` 保留异步状态。业务负责字符串与数值之间的转换及其校验，不能通过伪造原生事件适配。
- 音乐与影视分类导航复用 `view-tabs` 外观，使用 `aria-current="page"` 的导航语义；页签使用 `aria-selected`。两者使用同一选中态，包含主题填充、反色文字、分隔线与左侧状态轨。影视分类在窄面板内继续换行，TV 保留遥控焦点与放大的操作面。
- 共享面板的服务概览与协议区块复用 `Section`：协议图标进入标题左侧固定图标槽，状态与新增操作进入右侧操作槽，窄容器内操作换行。可拖拽区块只在外框保留一层主题结构线，内部不重复绘制边框；概览事实复用 `DescriptionList`，服务和共享记录采用结构线分隔的列表，不叠加圆角卡片、局部按钮或输入框外观。业务样式在 `app` 层维护布局，避免旧管理卡片样式覆盖共享组件。新增、编辑和删除弹窗复用 `DialogHeader`、`DialogActions` 与共享字段，保留视口居中、正文滚动、底部操作区及关闭后的焦点恢复。现有分组、布局编辑、权限和确认流程保持不变。
- 创建流程复用 `create-form-*`，Docker 不得引用 VM 的样式类。字段复用公共表单表面和焦点；弹窗复用 `ModalPortal`、`useModalDialog` 与 `modal.css`，业务只调整尺寸、正文布局和信息排列。状态标记与反馈由共享 `StatusBadge`、`Notice`、`EmptyState` 及 `@cyberos/ui` 的组件样式承载，旧 `components/status.css`、`components/feedback.css` 仅保留兼容定位和元数据规则；技术元数据复用 `metadata`。
- 存储文件与目录选择器复用 `DialogHeader` 的图标、眉题、标题和关闭操作插槽，图标位于标题左侧，不能与眉题一起塞入右侧操作区。专用 `files/picker*.css` 在 `app` 层维护结构与布局，存储池和文件行沿用主强调色选中面及配套反色文字，名称、路径、大小和图标一起继承选中颜色；状态徽标、空态和错误复用共享组件。图标底板保持直角，页头切角只作用于装饰层；工具按钮和输入框保留共享尺寸、禁用与忙碌态，移动触控至少 `44px`。保留桌面存储池侧栏、窄屏横向存储池列表、内部滚动和底部确认区，不改变文件筛选、目录边界及创建目录的审批流程。

拆分归属、整改项和验证入口见[前端样式维护清单](/docs/reference/frontend-styles/)。

## 6. 动效

动效模拟短促设备状态切换，不模拟故障闪烁。

- 启动屏使用一次诊断面板揭示和扫描进度。
- Agent / Workspace 首次挂载使用约 `260ms` 的短揭示。
- 当前会话、当前面板和设置导航使用约 `160ms` 的状态轨跳变。
- 设置只在正文区域使用 `160ms` 淡入，切换时不重挂载导航、标题或表单来触发动画，保留草稿、焦点与滚动语义。
- 管理面板在首次数据就绪后使用 `240ms`、`4px` 的短揭示；后台刷新、轮询、布局编辑和主题更新不重播入场。
- 通知中心与 Agent 审批只对当前可见区域内实时新增的条目使用 `160ms`、`4px` 入场，起始不透明度至少 `0.65`。首次读取历史、重新打开、切换通知页签或会话时不重播；流式文字和现有条目的状态更新不触发入场。Toast 沿用现有生命周期，入场与离场位移统一为 `4px`。
- 上述正文动效复用浏览器原生动画，不新增动画运行时依赖；内容默认可见，动画不阻塞操作。切换到减少动态效果时立即取消正在执行的揭示，结束或卸载后释放动画与监听。
- 文件目录切换只更新列表内容，使用约 `160ms` 的淡入与不超过 `4px` 的轻移；标题、存储池选择器、搜索工具栏、面包屑和表头保持挂载，不随目录请求替换为骨架。等待时保留原列表并降低对比、暂停旧行操作，在列表内显示忙碌提示；成功后一起更新路径和条目并重置列表滚动，失败则保留原目录和条目。键盘进入文件夹后焦点跟随列表，新目录第一项可继续操作；空目录保留列表焦点。短视口保留列表最小可用高度，允许文件工作区自身滚动，不能被顶部控件或底部播放栏挤没。减少动效模式取消位移和渐变。
- loading spinner 可以持续旋转；其他元素不得持续闪烁、抖动或循环位移。
- `prefers-reduced-motion: reduce` 下关闭面板揭示、状态跳变、骨架移动和非必要过渡；加载和错误信息仍可被理解。

## 7. 核心界面

### Agent 与聊天

- Agent 导航保持主题控制轨；会话使用编号层级，当前项使用强调色选中面并带强调色左轨。
- Agent 页头只展示会话编号、标题和会话操作，不重复显示“就绪”等运行状态徽标；连接状态保留在侧栏底部，任务反馈放在 Composer。
- Agent 首次加载的模块与数据使用同一完整骨架，保持导航轨、标题头、聊天记录和输入区尺寸；会话、历史消息、审批与模型配置的初始请求结束后统一展示，失败展示现有错误或未加载状态，不能永久停留骨架。历史消息在首次绘制前直接定位到底部，不能展示从顶部滚动的过程；离开并返回保留阅读位置，阅读旧消息时不因新内容强制跳到底部。
- Agent 会话切换只在聊天记录区域显示骨架与忙碌状态，会话导航、页头、输入区及侧栏底部入口保持挂载；选中项与标题立即更新，草稿保留且可继续编辑，加载期间禁止发送、删除和重试。快速切换只接收当前会话的结果，旧会话的审批与删除确认不得带入新会话；消息就绪后在绘制前恢复该会话阅读位置，骨架的滚动位置不得覆盖历史位置，也不重播整块面板入场动效。
- 消息是开放式分层记录，不使用圆角气泡。头像、左侧记录线、作者和时间共同区分用户与 Agent。
- Composer 是主题命令框，输入使用正文色，顶部次强调色短轨表示可输入状态；提交、取消和投递模式保持原业务语义。
- 审批卡使用硬边框和明确的允许/拒绝操作，不能弱化风险信息或跳过确认。
- 操作生命周期进入通知中心，不伪装成聊天消息。

### Workspace 与文件

- `PanelHeader` 继续承载图标、标题/副标题和直接操作。文件与其他面板复用相同的标题字号、图标、内边距和 `//` 前缀；移动端通过共享双层标题头保留这些层级。页头不添加重复统计或状态徽标；文件页头不展示存储池“就绪”等状态，也不保留状态占位列。
- 文件列表与搜索隐藏存储池根目录的内部 `.cyberos` 及其内容；普通隐藏文件和用户子目录内的同名目录仍正常显示。
- 文件列表使用硬分隔线和主题表头。hover 反色为主题选中态；选中行同时使用强调色轨和选择语义。
- 文件名列使用剩余空间并单行省略；桌面操作列为六个 32px 按钮、间距和内边距保留 242px。桌面窄容器不超过 620px 时隐藏大小与修改时间，操作列保留 88px，显示下载及更多。手机全屏文件 App 操作列仅保留 44px 更多入口，下载在菜单内；大小和时间移入名称下方，上传直接可见，批量选择有明确的选择/完成操作和 checkbox。
- 文件搜索保持紧凑单行；高级筛选使用 `SlidersHorizontal` 菜单，Escape 关闭并恢复焦点。
- 搜索结果只渲染纯文本和结构化高亮，不注入服务端 HTML。加载更多不能重排已有结果。
- 文件操作保留审批、安全路径、遍历防护和下载行为；视觉重构不得改变 API 或协议。

### 管理面板与终端

- 系统设置中的“代理”为独立分类，保存一组协议、地址与端口；具体服务通过共享 Switch 选择是否使用。TMDB 在元数据设置中显示代理摘要，并提供前往代理设置的入口。

- Docker、VM、网络、存储、共享、下载和监控保持现有数据流、表格和可编辑网格。
- Docker daemon 配置入口统一放在“系统设置 → Docker”，Docker 工作区页头不再保留该入口；编辑、保存及重启确认继续使用原有弹窗，关闭内层弹窗后返回 Docker 设置并恢复入口焦点。
- 有线网口首次发现时以中性“未托管”状态展示，不把自动导入的现有配置或默认草稿计入待应用项。网口设置明确提供接管入口和保存接管配置操作，保存后才显示待接管；应用仅包含明确保存的待生效端口，继续保留断网确认与自动回滚。
- 有线网口编辑中的 IPv4、IPv6 地址模式与 DNS 模式统一使用共享 `CustomSelect`，禁止原生 `<select>`；沿用公共选项菜单、键盘选择与禁用状态，Escape 先关闭选项，再关闭编辑弹窗。
- HUD 区块无圆角，使用结构线、主题强调轨或硬偏移底板建立层级；页面区块之间不要再套卡片。
- 无线网络状态卡片复用通用管理卡片的边框、标题栏和操作按钮，默认占据整行；布局编辑时与其他卡片一样支持拖拽及宽高调整，不设置专属尺寸上限。旧版固定尺寸只在读取已保存布局时迁移，后续用户调整继续保留。
- Share 按 SMB、WebDAV、FTP、NFS、DLNA 分为独立协议区块，默认各占整行；服务区块汇总真实运行状态。协议内新增、编辑、启停、删除独立提交，禁用保留归属。每条共享必须有明确协议归属；编辑弹窗复用全视口模态与焦点管理。
- 共享列表以名称为主层级，路径和连接标识使用带图标的紧凑元数据行；启停状态与开关成组，编辑和删除使用同尺寸的直角图标按钮，并与开关留出结构间隔。列表中的删除入口使用主题表面和危险色图标，确认弹窗保留明确危险命令。协议区块容器不大于 `520px` 时，操作区下移为整行，启停在左、编辑和删除在右；长名称和路径安全换行，不能挤压操作面或产生横向滚动。
- 共享新增和编辑表单使用单列配置行：宽屏标签固定列宽，控件统一左边界；窄屏标签移到控件上方。单行输入和 `CustomSelect` 统一 `40px` 高度及内边距，协议开关使用文字在左、开关在右的紧凑整行布局。表单样式必须作用于弹窗自身，不能依赖工作区祖先；长表单只滚动正文，底部操作保持可见。
- 布局编辑模式、拖拽抓手、键盘移动、调整尺寸和本地持久化保持现状。小于 `620px` 时固定单列并禁用拖拽缩放。
- 终端、控制台和代码区使用当前主题的高对比表面，颜色从 CSS 令牌读取。主题切换不得作为重绘依赖。
- 本机终端采用标签与工具栏、按需展开的搜索栏、终端画布和紧凑状态栏；tmux 只负责保活，CyberOS 管理会话的原生状态栏隐藏，不接管原生窗口、分屏或用户 tmux 配置。状态栏展示真实连接状态和终端尺寸，不将初始目录显示为实时工作目录。
- 终端搜索只覆盖浏览器已加载的当前会话输出，关闭时清除高亮并恢复终端焦点。工具栏提供复制选区、粘贴和浏览器全屏；小于等于 `560px` 时保留搜索，其余新增操作进入“更多”，触控区域至少 `44×44px`。主题、搜索、全屏和视口变化不得重建终端实例或创建新连接，只重新计算并同步尺寸。
- 终端所有粘贴入口使用同一安全检查：普通单行文本直接粘贴；包含换行或控制字符时先展示纯文本预览，控制字符必须可见，确认前不发送输入。确认绑定会话与当前连接，切换、重启、断开及接管后失效；保留 bracketed-paste，不额外追加回车，不截断或自动拆分超过 `64 KiB` 的最终输入载荷。剪贴板 API 不可用或被拒绝时提供手动文本框，不得误报复制成功；保留 `Ctrl+C` 中断、原生粘贴及中文输入语义。

### Photo、预览与编辑器

- Photo 查询区使用主题控制轨，时间线和地图使用主题媒体面。缩略图选择同时显示强调边框、选择控件和 `aria-pressed`。
- Photo 筛选弹层保留类型、相机、镜头、日期、曝光、评分、位置、关键词和高级元数据条件；关闭不提交草稿，重置保留文本搜索。
- storage pool、媒体路径和正常状态不占常驻信息栏。只有降级、离线、Worker 异常或稳定错误码在工具栏显示可聚焦异常入口。
- Photo 时间线保持 API 顺序、日期分组、真实宽高比、多列瀑布墙、游标分页、延迟加载和分页重试。地图视图不启用时间线分页观察器。
- 扫描期间仅在时间线首屏、未选择、未打开查看器且未分页时后台替换结果，最多每 5 秒一次；请求期间发生选择、打开查看器或翻页时丢弃该后台结果。分页与查看器保持当前快照，筛选统计和字段目录在扫描结束后统一更新。
- 灯箱、文件预览和编辑器使用主题媒体框、强调色控制轨和明确区分的选择/危险状态。关闭按钮、Escape 和焦点恢复保持可用。
- 灯箱通过全局 Portal 挂载，响应式布局必须使用视口断点，不能依赖 Workspace 容器查询。窄屏将元数据移到媒体区下方并限制其高度、独立滚动；短视口始终为图片和关闭操作保留可用空间。

### Music 音乐库

- 音乐来源管理统一位于“系统设置 → 媒体库”的全行音乐库块，集中提供目录选择添加、启用、扫描、扫描状态与确认移除；移除保留原始文件。音乐工作区不保留右上角管理入口，空库和扫描异常入口直接打开媒体库设置。音乐库独立加载与重试，影视或 TV 状态异常不能阻断音乐来源管理。
- Music 与 Photo 并列，采用概览、专辑、艺术家、歌曲和歌单横向导航。以真实方形专辑封面为视觉主体，保持共享主题令牌、零圆角和紧凑密度。
- 音乐与影视的查询工具栏置于页头下方、内容导航上方，页头图标操作统一为 32px 按钮和 17px 图标；查询控件统一参照文件面板：单行搜索框加右侧 `SlidersHorizontal` 图标按钮。来源、年份、类型、排序、收藏及观看状态等条件放入共享 `SearchFilterPopover`，不占常驻工具栏；所有下拉使用 `CustomSelect`，禁止原生 `<select>`。浮窗复用文件筛选的尺寸、字段、操作区与 HUD 样式，应用和重置后关闭并恢复触发器焦点；重置保留当前文本搜索及所在合集，Escape 或点击外部关闭时不提交草稿。嵌套下拉展开时，Escape 先关闭下拉，再关闭筛选浮窗；窄屏和短视口下内容在浮窗内滚动。
- 音乐年份、流派使用 `CustomSelect`，包含“全部”选项；选项来自所选来源的完整音乐库元数据，去重并省略空值，年份从新到旧排列，不得从当前分页推导。加载与重试状态留在筛选浮窗中，切换来源或关闭时取消旧请求；选择只更新草稿，点击应用后才生效。
- 音乐按面板容器宽度响应；容器小于 `620px` 隐藏歌曲专辑列，小于 `360px` 固定两列封面。队列和歌词放入可关闭抽屉，不创建常驻三栏。
- 音乐控制遥控 NAS，共享播放控制按“此设备 / NAS”区分浏览器影视与 NAS 音乐或影视，显示各自实际输出与播放状态。桌面 Web 左侧入口始终可用，默认关闭浮窗，入口不显示状态点；无内容时显示“暂无播放”，打开不触发播放。浮窗常驻音量、实际输出摘要与适用的切歌、停止及队列操作，设备切换和影视音频设置按需展开；歌词和完整队列继续使用正在播放详情。窄屏 Web 与 TV 使用底栏与输出图标浮窗。
- 音乐与 NAS 影视共享一个播放会话；浏览器影视独立播放。NAS 跨类型接管前明确确认。音箱失联、NAS 或播放服务重启后保留队列并等待手动恢复，不自动改用其他音箱。
- 队列提供拖动及键盘上移/下移；歌词以文本渲染，LRC 根据服务端播放进度高亮。来源路径与正常扫描状态不占主面板常驻信息栏。

### Video 影视库与公共播放

- Web / TV 共享首页、电影、剧集、合集和待看导航；首页按继续观看、下一集、最近入库、待看排列。以真实海报为主体，未知技术能力不显示推测徽标。
- Web、手机浏览器与 TV 的影视面板统一按容器宽度换行：首页各组和分类列表均使用自适应海报网格，分类导航、季数选择与操作按钮允许多行，内容通过面板纵向滚动访问。长合集名称、详情及技术信息安全换行，海报标题保留省略显示；面板内不得产生横向滚动，焦点环需完整可见。TV 保留远距离阅读字号和遥控操作面。
- 详情使用海报、简介、播放命令、多版本和分季选集；小容器堆叠信息，海报墙在最窄容器保持两列。来源、扫描和匹配纠错放入管理入口。
- Web 默认“在此播放”，TV 播放使用明确的独立命令。视频画面继续使用现有播放窗口；桌面左侧小浮窗只显示信息和控制，不复制视频节点。全屏时关闭小浮窗并隐藏移动底栏；最小化保留视频节点、进度与音量。
- 桌面 Web 小浮窗在入口右侧留出 `24px` 间距并与入口底边对齐，通过 Portal 挂载到应用外层，默认宽度 `360px`，限制在视口 `16px` 安全边距内；空间不足时向入口上方或下方避让，保持入口可点击，短屏允许内部滚动。浮窗使用 `2px` 强调边框。控制设备、文字状态与关闭按钮合并为紧凑顶栏；媒体区使用 `72px` 方形封面、约 `18px` 的两行标题与次级艺术家信息，不套按钮底板。其后依次排列进度与时间、居中播放控制、单行音量和底部工具区，普通音乐状态、输出收起时高约 `360–400px`。主播放键为 `48px`，前后曲及其他交互区域至少 `44px`；主强调色大色块集中在播放主键，保留主题表面、直角和偏移叠影。侧浮窗滑杆使用细轨、小型直角滑块和草稿值填充，保留 `44px` 操作高度；这些布局与滑杆外观仅作用于侧浮窗，不覆盖移动端与 TV 底栏。
- 小浮窗为非模态 `dialog`；重复点击入口、外部点击、关闭按钮或 Escape 关闭。内部 `CustomSelect` 展开时 Escape 先关闭下拉，再关闭小浮窗并恢复入口焦点；关闭按钮同样恢复焦点。打开详情或队列前关闭小浮窗，详情关闭后返回持久入口。进入窄屏时关闭桌面浮窗，改由公共播放栏承接控制。
- 桌面浮窗开关独立于底栏的 `sessionStorage` 偏好，默认关闭。开关只影响界面，不暂停、停止、清空队列或切换输出；播放 Provider、浏览器视频节点持久挂载，正在播放详情由当前布局承接。
- 窄屏 Web 与 TV 的底栏在独立底部网格行分配空间，不能覆盖主屏 Dock、内容或输入区；最底部可见行承接安全区。TV 使用较大的遥控操作面。收起后改为紧凑恢复入口，TV 高约 `61px`。“收起播放器”使用向下箭头，保留标签页内的展开偏好及静态状态标记；收起后聚焦恢复入口，展开后聚焦播放/暂停按钮，浏览器全屏时隐藏。TV 与 Web 复用同一播放控制内容与目标路由。
- 播放控制的设备选择始终明确控制对象；NAS 播电影时保留音乐队列入口。不同设备的操作不能隐式作用到另一端。
- 桌面播放浮窗常驻“音量图标、提交式滑杆、百分比”一行，底部并列输出摘要、队列及适用的带标签停止按钮。输出摘要取服务端实际输出，不以待提交选择代替；未知或不可用时显示明确状态。NAS 输出入口在卡片内展开设备选择、明确的切换操作及适用的音轨、字幕、延迟、静音设置，不重复音量；每次打开浮窗或切换控制对象/会话时默认收起。选择设备只更新草稿，点击切换后才提交；重新展开从当前配置初始化草稿，失败时保留实际输出摘要和错误。浏览器播放显示本地输出说明。展开触发布局重新测量，不能超出视口。窄屏 Web 与 TV 底栏的音频输出入口使用带本地化 `aria-label` 和 `data-tooltip` 的音量图标按钮，输出浮窗向上展开并限制在视口内；Escape 关闭并恢复图标焦点。
- 播放浮窗与音频输出浮窗内的设备、音轨、字幕等下拉统一使用共享 `CustomSelect`，禁止原生 `<select>`，不得仅用 CSS 隐藏原生外观；共享输出设备选择器也遵循此约束。展开选项在视口内保持可见，短视口允许内部滚动；Escape 先关闭下拉，再关闭浮窗并恢复入口焦点。`eslint.config.js` 对全部 Web TSX 执行此限制。
- 播放、音量和进度控件复用提交式滑杆，拖动结束后提交；输出切换必须明确执行。遥控焦点使用共享次强调色焦点环，TV 增大操作面和文字密度。
- TV 原生全屏视频的播放控制绘制在播放器画面内，采用同一 HUD 调色板、硬边结构与次强调色遥控焦点，水平居中并位于画面偏下位置；不能依赖被原生播放窗口遮住的 Web 播放条。浮层提供进度、前后跳转、暂停/继续、音轨、字幕与返回媒体库；音轨和字幕使用方向键选择真实轨道，字幕包含关闭项。播放中闲置 5 秒隐藏，暂停或轨道菜单打开时保持显示；确定或方向键可唤回，返回先关闭轨道菜单，再退出视频并保留浏览上下文；Home 发送独立导航意图后退出视频，页面收到新意图回到影视首页，忽略历史或重复意图。这里的全屏临时浮层与占据应用骨架独立行的公共播放条分别服务播放和浏览场景。
- TV 浏览层统一处理遥控返回别名（Escape、BrowserBack、GoBack、461）与 Home / BrowserHome。返回每次只关闭最上层菜单或弹窗，再从详情退回原海报、合集内容退回合集、分类退回首页；忙碌确认不可关闭。Home 关闭可关闭层并直达影视首页；正在播放的 NAS 视频停止，音乐队列和播放不受浏览导航影响。只有确定键激活焦点按钮，媒体键只分发到当前播放目标及其会话。
- TV 按导航栏、海报网格、详情、季数选择、选集和播放栏划分方向导航区域。海报网格、分类导航和季数选择按实际视觉行列移动：左右键在当前行内移动并停在行边缘，上下键优先进入相邻行中最接近同列的项目，到首行或末行才切换相邻区域；内容区域之间优先连续浏览，返回区域时恢复最后焦点。详情就绪后聚焦播放主操作；退出恢复原影片及纵向滚动位置，原项消失时回退到邻近海报或当前导航入口。减少动态效果偏好下焦点滚动不使用平滑动画。
- TV 的搜索入口统一打开屏幕键盘；年份和类型从完整可见媒体库提供可选列表。中文组合输入、候选、虚拟键和结果分别管理按键；连续虚拟输入保留原按键焦点，候选确定后返回原按键，返回先取消当前组合输入。英文明确插入或删除文本。搜索分别显示等待、空结果、失败及重试；从结果进入详情后返回恢复查询、结果焦点和滚动位置。
- TV 选集行确定直接播放该集，保留跨音乐与影视的接管确认；版本选择使用共享下拉，短标签包含版本序号、已知分辨率、编码和大小，完整文件名、路径及轨道参数可展开查看。搜索候选字号为 26px、组合输入为 24px，选集主文字为 22px，播放时间与次级技术信息至少 18px；窄屏保持可操作的热区与可滚动内容，真实电视观看距离另行验收。

### 文档站

- 文档站采用精密技术手册的排版：主题实底、细结构线和克制的颜色，不在正文后叠加网格或扫描线。复用共享主题、直角控件和字体角色；主强调色用于主入口与当前项，结构色用于分隔线，次强调色用于交互焦点。
- 桌面侧栏为 `256px`，阅读正文最大宽度为 `720px`。保留 Starlight 的 `800px` 侧栏断点与 `1152px` 右侧目录断点；窄屏正文横向留白为 `16px`，桌面为 `32px`。宽代码、表格和图表在自身区域滚动，不能撑宽页面。大型 Mermaid 图表以可读尺寸放入有名称、可聚焦且支持键盘滚动的容器，避免压缩整张图导致文字过小。
- 文档长文正文为 `16px`、`1.8` 行高；页头标题桌面为 `32px`、窄屏为 `26px`，二级标题为 `22px`、三级为 `18px`，技术代码为 `12px`。字号固定，不随视口连续缩放。页头展示所属栏目、标题与 frontmatter 的说明，并保留跳转到正文的键盘焦点目标。
- 首页使用简短介绍、快速开始主入口和六个编号栏目纵向导览，不展示无内容的右侧目录。文章页保留侧栏、章节定位和前后页导航；选中项使用主题选中面、强调色细轨和匹配文字，避免大面积高亮干扰阅读。
- 代码复制、搜索和移动导航沿用现有语义与焦点管理。窄屏工具按钮、折叠入口和栏目链接提供至少 `44px` 触控高度；焦点外环完整可见。仅主要操作使用硬偏移底板和最多 `1px` 位移，其余反馈复用短促状态过渡，减少动态效果模式关闭非必要过渡。
- 文档基础映射在 `custom.css`，导航与页头、正文阅读、首页导览、搜索分别归入 `layout.css`、`content.css`、`home.css` 和 `search.css`；`appearance.css` 映射全部 14 种主题；文档与同源 Web 共用外观偏好，静态资源和搜索索引继续由 Starlight 构建。

### 设置、通知与弹窗

- 设置是使用主题表面、细分隔线和强调色当前入口的系统菜单。外观分类提供七套配色、明暗模式及语言偏好；常驻配置区使用开放式全宽区块。
- 设置导航按使用目的归类，固定为“常规 → 网络与连接 → 文件与数据 → 媒体与下载 → AI 与语音 → 系统与维护”，不混用“设备 / 工作区 / 管理”等宽泛分类。桌面与移动端共用 `SETTINGS_SECTIONS` 的分组及顺序；保留全部 25 项、原有页面 ID、入口、选中与返回行为，搜索同时覆盖分类、标题和说明，筛选后不重排结果。
- 组内顺序固定为：常规（概览、外观、系统身份、版本）；网络与连接（无线网络、蓝牙、代理、Tailscale）；文件与数据（文件与预览、索引器、共享、备份）；媒体与下载（照片、媒体、下载）；AI 与语音（模型 Provider、Pi Agent、MCP、Skills、Audio）；系统与维护（Docker、虚拟机、监控、告警、运维）。低频维护集中在最后，不改变设置保存与危险操作确认边界。
- 设置样式由 `styles/settings.css` 在 `app` 层统一接入；壳层、表单、设备、资源和告警规则各有专用文件，不在旧管理面板或全局移动样式中重复覆盖。表格预览等第三方 CSS 必须收束在 `legacy` 层；电子表格模块运行时注入的全局样式也经 `loadSpreadsheetPreview` 收束，不能覆盖系统设置的字段颜色、字体或间距。
- 桌面设置弹窗最大为 `1120×860px`，四周至少保留 `20px`，分类轨为 `240px`；分类项高至少 `40px`，选中面、反色文字和当前轨同步。导航滚动区为 `2px` 焦点环及 `3px` 偏移保留完整空间。详情页头统一图标、`20px` 标题和 `12px` 说明，正文使用 `20/24px` 内边距。
- 设置在 `1040px` 及以下使用全屏分类列表及详情页；返回先从详情退回分类。桌面继续使用居中设置弹窗。确认、编辑等真正模态弹窗始终通过 `ModalPortal` 覆盖整个视口居中，不能跟随全屏设置页改为局部定位。
- 设置入口立即显示包含菜单、搜索、当前页标题与关闭操作的轻量外壳，不等待详情模块或接口，不以入口长时间转圈代替打开。仅正文使用懒加载边界与共享骨架，外观和文件预览偏好直接可用；正文等待期间仍可搜索、切页、关闭及操作键盘，焦点环、焦点恢复与外壳尺寸保持稳定。
- 设置数据仅按当前可见详情页读取，手机分类列表不读取隐藏概览，Voice 与播放器直达目标页。原由应用集中读取的资源在一次打开内去重并保留已加载数据与草稿，重新打开按首次访问重新读取；已有自加载页面保留原生命周期。关闭前一轮的迟到结果与错误不得回写当前弹窗。并行配置和状态分别就绪，状态失败不阻断配置；读取错误与重试放在对应正文区块，详情模块失败仍保留菜单和关闭，并提供页面重新载入入口。
- Provider、Pi Agent、Docker、虚拟机保存仅提交当前页已就绪的配置，禁止将未访问页面的默认值联合写回；保存成功仅同步本资源并失效受影响的概览缓存。Agent 启动的 Provider 读取与设置复用仍在途请求，不能覆盖已编辑表单；原有审批、危险操作确认与失败保留草稿边界不变。
- 设置中的独立区块统一复用 `settings-page-grid` 的单列整行布局，媒体元数据、媒体库状态等按顺序上下排列；不得用页面局部样式将独立区块改成左右等分。
- 所有常驻配置区复用 `Section` / `SectionHeader` 的 `15px/24px` 标题、`12px/1.5` 说明、顶部结构线和透明底面；首块不再添加重复的顶部边线。强关联字段可以两列，详情容器不超过 `560px` 时转单列，不以整页视口宽度代替实际表单宽度判断。
- 字段统一 `Field` 标签与共享输入控件；标签行至少 `24px`，有无帮助图标都保持控件基线一致。输入与选择器桌面至少 `40px`，移动端至少 `44px`，均为直角；创建联系人、收件人等紧凑表单也保留明确标签。状态详情使用共享键值列表，正文和状态说明不得靠单行截断隐藏必要信息。
- 整页提交的表单仅滚动正文，主要保存操作固定在底部；共享账号、备份凭据、媒体元数据等独立提交区域继续在各自区块内提供操作，不合并保存边界。长资源名称、目录、错误和告警联系人在窄内容区换行，操作成组下移，不能挤出视口或遮挡开关。
- 设置内层编辑与确认弹窗复用 `DialogHeader` / `DialogActions` 的标题、说明和操作槽位，不保留旧图标列宽或原生按钮外观。加载、禁用和忙碌状态不改变命令尺寸；错误保留草稿，关闭恢复入口焦点，Escape 先关闭提示或菜单，再关闭当前弹窗。减少动态效果时保留静态状态，不增加设置页专属扫描或闪烁动画。
- 设置概览的所有区块共用标题栏：左侧固定 `24px` 图标位承载 `18px` Lucide 图标，与 `24px` 行高的标题居中对齐；图标位和文字间距为 `10px`，说明文字在标题下方同列起笔。标题栏底部使用 `12px` 间距和细分隔线，系统概况也必须提供图标；中英文和窄屏沿用同一结构，长说明自然换行，不改变标题的水平起点。
- **设置下拉框禁止使用原生样式**：所有设置页面、内部弹窗及设置复用的共享控件必须使用 `CustomSelect`，触发器和展开选项都遵循共享 HUD 样式。禁止使用原生 `<select>`；仅添加 CSS 或 `appearance: none` 不符合要求。保留键盘导航、选中与禁用状态、长文本省略、Escape 关闭和焦点恢复，展开菜单不得被滚动容器裁切。`eslint.config.js` 对全部 Web TSX 执行此限制。
- 密钥输入框的清除操作放在框内右侧，待清除状态使用文字占位提示并提供撤销；提交设置后才清除已保存的凭据，不另占一行 checkbox。
- **悬浮提示禁止原生样式**：Web 与 TV 中按钮、图标、状态、被截断的名称和路径等提示统一使用 `data-tooltip`，由 `TooltipLayer` 渲染；设置项的 `HelpTip` 复用同一个 `.hud-tooltip` 外观。禁止用 HTML `title` 提供悬浮提示，ESLint 必须拦截；iframe 的无障碍标题和组件的标题属性保留。纯图标操作继续提供本地化 `aria-label`，提示不能代替操作名称。浮层使用不透明主题表面、直角、细结构边框、2px 强调色左轨与克制的偏移阴影；邻近入口定位，长内容可换行和滚动，四周至少保留 12px 视口边距，空间不足时自动向上展示。鼠标短暂停留后显示，键盘聚焦立即显示，可移入浮层阅读；移出或失焦关闭，Escape 只关闭当前提示，不能同时关闭所在弹窗，点击操作不能被提示拦截。浮层通过 Portal 进入当前模态层或全屏层，不能被滚动容器裁切；Web、TV、窄屏及禁用控件遵守同一约束。
- 设置项的静态说明、参数帮助和安全提示统一放在对应文字后的 `HelpTip` 信息图标中，不另占常驻提示条或帮助行。鼠标悬浮、键盘聚焦和触屏点击均可查看；提示可悬浮阅读，Escape 先关闭提示，保留所在设置或弹窗，点击外部关闭。复用直角 HUD 浮层，邻近触发器定位并限制在视口内，通过 Portal 避免滚动容器裁切。提示按钮有本地化名称及关联说明，必须与字段 label、开关分开，查看提示不得修改表单、触发保存或切换开关。实时错误、校验结果、不可用原因和危险操作确认继续直接展示。
- MCP 的添加与编辑 Server 使用全界面居中的独立弹窗，设置页只保留列表和入口，不在正文内展开编辑表单。表单内容在弹窗内滚动，标题和底部操作保持可见；错误在弹窗内展示并保留草稿，保存期间禁止重复提交和关闭，关闭后恢复入口焦点。
- 备份仓库路径使用共享目录选择弹窗，不提供手填路径输入框。浏览范围限于备份目录和可用挂载位置，排除 NAS 数据、系统状态和暂存目录；更换路径后清除验证状态并关闭定时备份，先保存新路径再验证或初始化。目录选择本身不创建仓库，也不修改独立挂载校验。
- 无线网络设置页只展示网卡连接与热点状态。Scan 打开网络弹窗并扫描附近 SSID；选择、连接、编辑、遗忘已保存网络、射频开关和断开连接都在弹窗内完成。热点配置、启停和删除也放在热点弹窗内，保留风险确认和外部配置只读限制。
- Tailscale 设置按状态、本机信息、节点、网络和网关纵向展示。实时更新不覆盖未保存草稿；配置版本冲突时保留草稿并要求重新核对。网络变更显示 60 秒确认与恢复入口，断开、注销和重启使用共享确认弹窗；路由发布与控制面审批必须分别表达。
- 蓝牙设备主区只展示已连接、正在连接或已记住的设备；Scan 打开居中发现弹窗并开始限时扫描，附近设备发现与配对确认在弹窗内完成。设备行操作统一为带本地化名称提示的直角图标按钮，断开连接也使用图标；关闭弹窗后恢复 Scan 焦点并停止该弹窗发起的扫描。
- 通知中心使用主题 HUD 抽屉，未读项显示强调色状态轨；点击单项只更新该项，不意外关闭抽屉。通知入口、分类页签及待审批数字角标统一使用主强调色底板与配套反色数字，随主题切换，并与会话编号保持独立。
- 语音入口位于桌面播放器入口正上方，移动端位于 Agent 标题操作区及主屏通知旁；选中用主强调色，未读回复使用静态提示点。语音与通知抽屉互斥。语音抽屉桌面宽 460px，覆盖工作区；560px 及以下铺满视口，尊重上下安全区。顶部与录音区固定，中间独立滚动；用户靠右、Agent 靠左，按日期分组，短元信息显示角色、时间与来源。语音条共用一份浏览器播放状态，将同一回复的分段音频显示为连续进度。仅接近底部时跟随新消息；翻阅旧记录时提供“有新消息”，加载更早记录和重新打开时保留阅读位置。侧栏只提供录音、试听和发送，审批跳转完整会话。关闭按钮、外部点击、Escape 或移动返回均停止本地回放、结束录音并保留试听草稿，随后恢复入口焦点；后台停止采集与自动回复，减少动态效果时关闭滑入动画。
- 语音抽屉复用 `DialogHeader` 的左侧图标与标题插槽，右侧只放完整会话、Audio 设置与关闭操作。36px 图标底板的 8px 切角只作用于装饰层，标题沿用 `//` 工业标识；运行状态复用带文字的 `StatusBadge`，离线、待审批、录音和上传均表达真实状态，不用装饰性扫描或闪烁。历史采用硬分隔、方向状态轨和主题表面，避免消息框与音频控件重复套边框。录音与发送使用共享主命令，重录、加载和审批跳转使用次命令，停止录音使用危险命令，加载/禁用与焦点保留共享语义；错误和空态复用共享组件。专用 `voice.css` 在 `app` 层维护，过渡约 160ms，移动按钮与音频拖动热区至少 44px。
- Toast 固定在视口层级并自动消失；可追溯的生命周期信息进入通知中心。
- 对话框必须有标题、关闭操作、焦点进入、Escape 关闭和焦点恢复。危险操作保留明确二次确认。
- **所有模态弹窗在整个界面居中**：设置、确认、编辑、文件选择、预览和嵌套弹窗的遮罩必须覆盖整个视口，内容水平、垂直居中；位置不随触发入口属于左侧 Agent 或右侧 Workspace 而改变，也不相对局部面板、卡片或设置正文居中。统一使用 `ModalPortal` 挂载到应用根层，全屏播放时使用当前全屏层；禁止在带有 transform、容器查询或滚动裁切的面板内直接挂载遮罩。嵌套弹窗使用共享层级，保持顶层交互、焦点圈定和关闭后的焦点恢复；窄屏保留安全边距，长内容在弹窗内滚动。ESLint 拦截直接用原生容器创建模态遮罩的写法。
- 共享文件和目录选择器在窄屏短视口中保留可用的文件浏览高度，中央区域可滚动；存储池与路径工具栏不得把列表挤到确认按钮后方，标题和底部确认操作保持可见。

## 8. 文案与本地化

- 用户可见文案进入 `packages/web/src/i18n/resources.ts`，中英文保持短、直接、以操作和状态为中心。
- `Agent`、`Workspace`、`Docker`、`VM`、`NAS` 等术语保持稳定。
- 错误文案说明发生了什么和下一步动作，不泄露凭据、内部堆栈或不必要路径。
- 界面不显示设计说明、键盘教学或风格描述。必要帮助放入现有 tooltip、label 或文档。

## 9. 无障碍基线

- Tab 顺序与视觉顺序一致；Enter、Space、方向键和 Escape 行为保持现有语义。
- 装饰图标设置 `aria-hidden="true"`，图标按钮有可读标签。
- 对话框打开后焦点进入，关闭后回到触发器。菜单和弹层同样恢复焦点。
- 状态变化使用合适的 `role="status"`、`role="alert"` 或 `aria-live`，避免后台刷新反复打断读屏。
- 悬浮说明统一使用 `data-tooltip`，Web / TV 的 `TooltipLayer` 和文档站共用同一提示控制器及样式，禁止在原生元素上使用 `title` 触发浏览器默认提示；组件的标题属性和文档标题不受影响。提示复用主题表面、主题正文、强调色结构轨、直角和硬偏移叠影，挂载到独立浮层避免滚动裁切，并适配视口边缘及全屏层。鼠标悬浮延迟显示、键盘聚焦直接显示，可移入提示阅读长文本，Escape 关闭但不移动焦点；保留原有 `aria-describedby`，触控点击不触发粘滞提示，减少动态效果时关闭动画。
- 全部 14 种组合的正文和关键控件达到 WCAG AA。红色与青色状态同时提供图标、文字、结构轨或 ARIA 状态。
- 多面板中的悬浮提示只在触发器所属滚动容器或视口滚动时关闭；Agent 对话等其他区域的自动滚动不得中断提示的延迟显示或阅读。
- 焦点环不得被 `overflow`、`clip-path`、mask 或父容器裁切。

## 10. UI 变更准入

任何 Web、TV 或文档 UI 变更在交付前检查：

1. 是否覆盖七套配色的明暗模式、刷新恢复与同源同步，并复用 CyberUI 共享主题令牌、Oxanium / Noto Sans SC / Share Tech Mono 字体角色和零圆角几何？
2. 是否覆盖 default、hover、active、selected、focus、disabled、busy、error？
3. 是否在中文、英文和 `prefers-reduced-motion` 下检查文本、动效和状态表达？
4. 是否在 `1440/820/560/390/320px` 检查重叠、页面级横向溢出、触控区域和长文本？
5. 是否保持 Enter、Space、方向键、Escape、焦点恢复和屏幕阅读器标签？
6. 是否误改 API、审批、安全路径、通知生命周期、Photo 顺序或分页语义？
7. 是否避免引入第三方专有素材、持续闪烁和局部视觉分支？
8. 设置及其弹窗中的下拉框是否全部使用 `CustomSelect`，并通过禁止原生 `<select>` 的 ESLint 检查？
9. 独立内容区块是否默认一块占据一整行，避免无必要的二等分或多等分布局？
10. 从左右工作区及嵌套弹窗打开时，遮罩是否覆盖全界面、弹窗是否始终按整个视口居中，并保持层级与焦点行为？
11. 按钮是否全部保持直角，尤其是弹窗内的关闭、取消、保存和危险操作；各交互状态与 Portal 挂载后四角计算值是否仍为 `0px`？

至少运行相关 Vitest、`npm run typecheck`、`npm run lint` 和 Web 构建，并完成一次真实浏览器检查。发布前执行 `make ci`。视觉问题优先修复根级令牌或共享组件，不用页面级临时补丁掩盖。
